How each run works

  1. Ideas — a small LLM proposes candidate tool ideas based on what the site already has.
  2. Dedup — near-duplicates of existing tools are dropped (token overlap + title similarity + an LLM judge for borderline cases).
  3. Generation — a code model writes the tool as a self-contained HTML fragment with a strict structure contract.
  4. Quality gate — headless Chromium runs functional tests, accessibility and mobile-layout checks; zero-JS-error is mandatory.
  5. Publish — passing tools are wrapped in the site shell (SEO + ad slots), registered and the site is rebuilt.
  6. Ship — everything is committed and pushed; GitHub Pages serves the new pages within minutes.
